--->CORRIGIDO<--- Bug: aplicativo não está inicando com o Windows, deve ter a opção de iniciar com o Windows,
isso é prioridade, e por fazer parte de um sistema de segurança, deve ser um dos primeiros
a ser iniciados.
   Correção: o autostart agora é LIGADO POR PADRÃO na primeira execução (via Tarefa Agendada
   elevada, sem prompt de UAC no boot). A cada início o app re-sincroniza a tarefa: se ela
   tiver sumido ou o .exe foi movido/reinstalado, ele recria sozinho. A tarefa recebeu
   prioridade alta (Priority=4, acima do normal) e gatilho de logon sem atraso (Delay PT0S),
   para subir entre os primeiros. A opção continua na aba "Inicialização" (tela Avançado)
   para o usuário desligar se quiser — a escolha é respeitada nos próximos boots.


--->CORRIGIDO<--- Bug: ao terminar a instalação aparece o erro "Incapaz de executar o arquivo:
C:\Program Files\SML Defender Control\SMLDefenderControl.exe — CreateProcess falhou; código 740.
A operação solicitada requer elevação."
   Causa: o app exige administrador (requireAdministrator no manifesto). No Inno Setup, as
   entradas [Run] marcadas como "postinstall" (a opção "Iniciar o app" no fim) são lançadas
   com o token NÃO-elevado do usuário original — diferente das demais entradas [Run]. Ao usar
   CreateProcess num .exe que pede elevação sem token elevado, o Windows retorna o código 740
   (ERROR_ELEVATION_REQUIRED).
   Correção: a entrada [Run] passou a usar a flag "shellexec" (ShellExecuteEx no lugar de
   CreateProcess). O ShellExecute honra o manifesto requireAdministrator e dispara o UAC para
   elevar o app — exatamente o comportamento esperado de um lançamento manual. Versão do
   instalador e do app subiu para 1.3.1.


IDEIA FUTURA (não é bug; registrada a pedido do usuário): submenu nativo no menu CURTO do Windows 11.
   Situação atual: o menu de contexto "SML Defender" (Bloquear/Desbloquear na internet e
   Adicionar/Remover das exclusões do Defender) é criado por REGISTRO pelo instalador
   (classes exefile\shell para .exe e Directory\shell para pastas; pastas só têm exclusões,
   pois o firewall não aceita pasta). Cada item chama o próprio .exe em modo silencioso
   ("SMLDefenderControl.exe --block ""%1""" etc., já implementado no CliHandler).
   No Windows 10 o submenu aparece direto no botão direito. No Windows 11 ele aparece em
   "Mostrar mais opções" (Shift+F10), porque verbos baseados em registro NÃO entram no menu
   curto novo do Win11. (Obs.: a chave/valor "Extended" faz o CONTRÁRIO do desejado — ela
   esconde o item, deixando-o só no menu estendido; por isso NÃO foi usada.)
   Upgrade viável para aparecer NATIVAMENTE no menu curto do Win11: implementar um handler
   COM IExplorerCommand empacotado em um MSIX (sparse package) assinado. É um projeto à parte
   e bem mais complexo (COM + empacotamento MSIX + assinatura), por isso ficou como tarefa
   futura a avaliar por custo/benefício. O comportamento atual (menu clássico) está correto e
   funcional nas duas versões do Windows.
